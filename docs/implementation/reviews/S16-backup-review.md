# S16 / S01 完整备份恢复独立审查

日期：2026-10-03。范围：`desktop/src/services/backup.cjs`、store、workbench、main IPC 与设置页面接入。新增独立回归测试 `desktop/tests/backup-review.test.cjs`。本报告不把迁移或打包发布判为完成。

结论：通过本轮本地完整备份恢复的有限范围复审；发现的问题已由实现方修复。真实原生对话框、平台兼容性与大体积压力测试仍待验收。

## 审查期间确认并修复

- 导出未验证当前 profile。原实现面对损坏或缺失资料仍返回成功，但同一备份随后无法预览/恢复。实现方已在导出前校验当前资料；独立测试通过。
- 原件只检查叶文件，`.workbench/assets` 目录为符号链接时会跟随并读取受管目录之外的数据。实现方已逐级拒绝链接；独立测试通过。
- 恢复 `parseStatus: processing` 后没有解析 worker，却一直显示“正在解析”。实现方将其转换为可重试的失败状态；独立测试通过。同时 running/queued AI 工作改为 interrupted，不重新请求供应商或自动扣费，独立测试通过。

## 追加复审已关闭

1. **连接凭据及状态恢复边界：已关闭。** 原实现只在导出清理 credentials，构造的结构合法归档可在恢复时带回 connected/secret。实现方已在导出和恢复两处使用元数据字段白名单，强制 disconnected/credentialsMissing；独立测试验证归档中注入的 secret 不落入恢复数据库，状态也不再 connected。
2. **原生目录框等待期间的恢复票据竞态：已关闭。** 原先 await 后才捕获全局票据，期间新的 preview 可以替换它。现已在 await 前捕获并消费本次已校验的票据，并在目录对话框返回后再次校验期限。代码复审确认这消除了全局票据替换与双重消费；未进行真实原生对话框并发测试。

## 验证结果及边界

命令：`node --test desktop/tests/backup.test.cjs desktop/tests/backup-review.test.cjs`。复审后 **9/9 通过**，其中 6 项为本审查新增。

- 原件字节、当前资料、历史版本及任务经独立新目录恢复；旧工作区不会自动切换。
- 缺失原件、错误文件哈希、路径穿越、预览后归档变更均拒绝；新增缺失原件测试确认没有创建恢复目录。
- 路径白名单拒绝反斜杠、绝对路径、空段、`.`、`..`，恢复文件使用新目录及 `wx`；目录写入失败会清理本次新目录。路径与原件测试不能替代存在恶意本机进程时的 TOCTOU 防护。
- 压缩文件与解压 payload 均限 256 MiB，文件数限 10000，解压使用 maxOutputLength。按代码审查确认该上限，未生成 256 MiB 压缩弹进行内存压力实测；JSON、base64、Buffer 的同时存在会使实际峰值内存明显高于 256 MiB，当前同步处理也会阻塞主线程。
- DB 导出使用同步 SQLite 事务，单进程 JS 写操作不会在同步文件收集中穿插；这不构成跨进程同时编辑知识库与数据库的全局快照保证。
- 业务记录 ID 与原件内容哈希保留；SQLite restore 会推进 revision 和 updatedAt，以使旧编辑器失效。未额外迁移旧数据库版本或重建不存在的业务引用。
- 白名单不会包含 Electron userData 的模型密钥和网页登录 partition。知识库由用户自行写入的文本按原文备份，不代表自动识别并去除任意文件中的敏感文字。
- 未实际点击 macOS/Windows 原生导出、预览、恢复目录对话框，也未验证 Windows 文件名兼容性、跨版本迁移、安装包或签名发布。

审查仅添加测试与报告；产品修改由主实现方执行。
