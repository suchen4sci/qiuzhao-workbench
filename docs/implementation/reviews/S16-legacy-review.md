## P2：空选择提交消耗预览票据，补选后仍无法完成导入

位置：`desktop/src/ui/workbench.js:237` 与 `desktop/src/main.cjs:174`。

预览表单只要求用户勾选确认，不要求至少勾选一行。用户勾选确认但未选行时，IPC 先将 legacyTicket 清空，再调用 migrate；migrate 抛出“请选择记录”。弹窗仍保留，用户随后补选一行并再次提交，却收到“请重新选择并核对旧版文件”，必须关闭并重新进入文件选择流程。

复现已用 VM 执行实际 main.cjs 的 legacy-import 分支验证（替代 migrate 仅执行空 ids 校验）。第一请求得到“请选择记录”，第二次同 token 加上有效 ids 得到“重新选择”。未操作真实 GUI，不将此验证称为完整端到端点击测试。

建议：表单在发送 IPC 前拦截零选择；主进程对可纠正输入校验失败保留有效票据，或在失败后明确进入可重预览流程。成功迁移后仍消费票据，过期和文件哈希变化仍必须重新核对。

## 验证结果

独立七项测试在系统 Node v25.9.0 和 Electron 44.4.3 内置 Node v24.21.0 下均 **7/7 通过**：

1. 只导入勾选条目；原文件字节不变，完整原记录在 evidence 保留，notes 包含所有字段与值；旧二面状态、模糊日期不生成申请、事件、任务、提醒或活动。
2. 完全重放不增加或修改记录；已导入旧 ID 内容变化拒绝覆盖；预览后源文件变化拒绝导入。
3. 无显式确认、空/未知/重复选择、重复旧 ID、非法字段类型均拒绝且无写入。
4. 故障注入到第二条 collect 时，已写第一条及第二条全部回滚；复用的既有单位类型、网址和版本不变。
5. javascript 链接不进入机会可打开 URL，但原始证据完整保留；附件目录路径仅作文本保存，无资产导入；符号链接源文件拒绝。
6. 核对操作要求确认与观测版本，完成后证据不变，也不自动登记申请。
7. 无旧 ID 的完全一致记录去重；内容变化产生新记录，界面已有明确提示。

## 接口与 UI 静态核对

- 文件选择由主进程对话框完成；IPC 通过随机 token、五分钟有效期、主进程保留的 hash 绑定文件。渲染端传入 hash 不能替换票据 hash。
- 导入机会的开放状态 unknown、statusVerified=false，并进入待确认箱；确认箱能查看经 HTML 转义的完整原记录并标记已核对。
- 危险链接与旧附件只在转义后的原文中显示，不主动读取附件或执行链接；源文件通过 O_NOFOLLOW 与 fstat 检查读取。
- 预览为公司/岗位/旧状态摘要，原记录在确认箱核对；本次未验证大规模真实用户旧文件、真实 GUI 文件对话框或 Windows 文件语义。
