## 必修发现与修复

1. **偏好变化后仍保存旧范围晚到结果（P2）。** 原 tick 仅在发请求前检查 signature，等待请求期间偏好改变后，仍写入原方案结果；预算 1 时甚至将轮次标 ready。修复后 await 返回再次检查签名，停用调度并标 cancelled，旧结果不入 snapshots。另到期检查前也核对偏好，24 小时等待期内的变化立即暂停，不拖到次日才提醒。
2. **同卡多路线被首路线大量别名长期占用（P2）。** 原单卡先遍历某路线的全部维度/别名才进入下一路线；每日预算较小会让后续路线连续多天无法检索。修复后卡内各路线交替、卡间再交替；独立验证一张含四路线和大量技术别名的卡，前四条覆盖四路线。
3. **考研使用企业技术岗位别名。** 主实现补修 postgraduate + direction 仅使用原始方向标签，避免自动套用工程师、运维等招聘词。独立测试修复前失败，修复后通过；这不代表已有完整研究方向语义词表。

## 已验证行为

- 原始路线、明确全局路线和排除路线共同限制查询；“只看考公”不会生成企业或考研查询。各条件拆为路线加单维度检索，候选检索不强行把所有标签串成窄交集；具体资格、其他条件与开放状态需后续原文核对。
- 企业/招录方向扩展既有别名，方案交替且多路线交替。用户关键词引用为单行字面量，移除换行、反斜杠和引号等注入查询结构的字符。
- 不添加当前年份或 freshness 限制，因此不只找新发布页面，也保留可能仍开放的存量线索。搜索命中不构成仍可申请的证明。
- 默认关闭；启用需最新方案 signature、显式费用确认、有效搜索连接及 1–10 次预算。重复检查、重新保存配置和应用重启不会突破已预留 24 小时窗口。
- 发请求前预留轮次与推进 cursor，失败、取消或结果不明不自动重放；所有每日请求与手动搜索共享本工作区滚动 24 小时 20 次上限。
- 停用每日设置、取消本轮及关闭服务会传递 AbortSignal；即使供应商忽略信号并晚回，结果也不会入库。停用搜索连接中断 provider 请求并终止剩余派发。
- 关闭时 running 轮次成为 interrupted；重启恢复 running 记录时标 interrupted，不立即重试。下一到期轮次从已推进位置继续，避免重复不确定的付费请求。
- 单个请求失败时保留此前已收到的结果、轮次标 failed；不伪称完整覆盖。当日不自动补发失败调用。
- 结果独立保存为 preference_search_result snapshots，重启可读；同 URL 汇总全部查询、方案、路线和时间证据。后续结果更新标题/摘要及 lastDiscoveredAt，保留 firstDiscoveredAt。
- 不自动新增 organizations/opportunities/application/task，也不把发现时间写成开放日期。保存搜索线索与用户确认导入招聘事实是不同步骤。
- Workbench 提供 preview/configure/check/results/cancel，snapshot 暴露调度状态；close 先关闭 daily search，再关闭底层 search 与 store，晚回路径不会写已关闭 store。

## UI 与范围限制

静态复核当前 UI：显示总查询数、接下来最多 10 条、轮转位置、每 24 小时至多一轮、停机不补多轮、每查询第一页最多 10 条；确认文案说明持续发送路线/标签/别名、供应商费用与共享上限。已保存线索按 20 条分页，并显示全部证据与“读取原文并核对”入口。UI 明确新发现不等于新开放，标题和摘要仍未核实。

这条路径仍是固定供应商的有限第一页检索，未证明全网召回率、没有全量语义检索、没有自动核验所有开放/资格事实，不能据此关闭 Plan 的完整 F2 或 D5a 召回评测门槛。搜索证据页也不替代已导入岗位的个人条件匹配与新开放/存量分类。未运行真实供应商付费请求；独立 UI 检查为源码检查。主实现另提供真实 Electron / IPC 冒烟通过结果：配置、保存每日预算、关闭授权与空线索视图；未发生真实付费搜索。这项 UI 冒烟由主实现执行，不计入独立 18 项测试。
