# F2 机会浏览与批量计划缺口审查

审查日期：2026-10-03。对照 Plan F2 / F2.3，阅读 `src/ui/workbench.js`、`src/services/workflow.cjs`、`src/services/matching.cjs`。本轮仅代码审查，没有修改实现，未将静态阅读当成 UI 验收。

## 结论与可实施范围

1. **单位聚合缺失。** `workbench.js:96–98` 直接 `list.map(opportunityCard)`，仅统计岗位/项目数。同一单位的不同岗位、批次重复展示单位标题。应按稳定 `organizationId` 聚合，显示单位数与岗位/项目数，展开后逐岗保留批次、城市、全部命中方案和加入计划入口。多个方案命中仍只计一个 opportunity；不同岗位和批次绝不能被聚合逻辑删除。
2. **列表维度筛选缺失。** 当前只有 `filterTier` 状态与层级按钮，路线/方向/城市/单位性质仅为卡片上的文字标签，没有筛选事件；也没有单方案选择。需要路线、方向、城市、性质、方案选择器及清空筛选；同维度多选 OR，维度间 AND，并与层级组合。单方案按 `match.matchedPlans[].id` 选取，不重新扩大或改写已保存偏好。明确“已加载机会”的统计范围，空状态允许一键清空筛选。
3. **多选加入计划缺失。** 当前 `plan-add / company-plan` 逐个调用 `plan`，默认直接把日期设为今天。需要可见选中数量、全选当前结果/清空、批量操作弹窗，统一选择日期、优先级和可选提醒。筛选后隐藏的选中项须清空或明确展示，不能悄悄批量操作不可见条目。
4. **公司清单导入缺失。** 仅有单个 `company-new` 表单，链接读取及旧版迁移都不等于公司清单导入。最小可用方式为多行粘贴清单，明确列格式（名称、机构类型、官网可选）→ 预览规范化结果及重复/错误 → 确认导入。导入创建/复用单位并关注，不虚构岗位、计划或来源覆盖；若用户另选加入计划则只建 awaiting_role。
5. **批量后端与关注闭环需要补齐。** `workflow.plan` 有单项去重和事务，但没有批量 API；`watch` 独立存在，单项 `plan` 也不会确保关注单位。批量应先完整校验输入，事务内保存，重复重试不产生重复计划/任务；保留已存在计划的日期与优先级，除非用户明确选择覆盖。所选单位按 F2 进入关注清单。已有完成/进行中计划不可被批量操作重新创建为待投递，也不应静默改期。

## 已有基础可以复用

- 匹配结果携带全部 `matchedPlans`，可支持单方案过滤，不必再次实现匹配引擎。
- 机会已有 `route / nature / direction / city / organizationId / batch`。
- `workflow.organization` 使用名称+类型确定 ID，`workflow.plan` 使用单位+机会确定 ID，并支持公司级 awaiting_role。
- 关注区已逐单位显示来源覆盖状态；批量导入应沿用真实覆盖状态，不能因新增关注自动标成已监控。
- Logo 当前使用名称缩写，符合允许的占位方式。缺少核验来源时不必为了本次聚合虚构官方 Logo。

## 独立回归清单（实现后执行）

- 同单位两岗位、不同批次仍保存为两项，聚合一单位；另一单位单独成组；多方案命中不翻倍计数。
- 各维度单独筛选、同维度 OR、跨维度 AND、层级组合、单方案及不存在方案、未知字段及空结果；清空后恢复完整相关列表。
- 仅选单位建立 awaiting_role；选具体机会建立 planned；同单位同时选公司与岗位的行为明确，不悄悄额外产生待选岗位任务。
- 重复提交、重复输入、已有计划、已完成计划、无效 ID/日期/优先级、任一条失败后的事务回滚；无伪造申请与活动。
- 提醒时间与工作台时区一致；已有计划默认不被批量日期覆盖。
- 清单重名同类型复用、不同类型保留区分、大小写/全半角/首尾空白去重、非法网址、超限输入、重复导入；已有官网/性质不能被清单空值覆盖。
- UI 验证选择状态、筛选后的选中行为、批量结果反馈、键盘操作与零数据空状态。

该范围补齐的是 F2 浏览和管理链路；自动发现的真实覆盖、语义召回与每日摘要仍须沿各自审查项验收，不能用本轮通过替代。
