## 初审发现与复核

1. **同日改时被丢弃（P2，已修复）。** 初版以 fromDay===toDay 过滤改期，丢失同日 09:00→15:00。现比较完整 schedule，事件 history 保存旧开始/结束/截止与新 toSchedule，返回 destination。独立同日测试通过。
2. **只变更结束或截止时 UI 信息不完整（P2，已反馈）。** 初版 calendarDayHTML 用 startsAt 优先显示旧新时刻，开始不变时会显示相同时刻，即使真正改变了结束或截止。应显示开始/结束/截止的独立摘要或变化字段。最终结果见补充。

## 静态路径检查

- 服务返回 planned/completed/changes 三组详情；UI 有独立标题、结果、来源、历史去向、变更邮件及面试复盘入口，不再只有任务当前快照。
- 旧历史无 toSchedule 时以后一条 reschedule 的旧值重建当次目的排期；新记录直接保存明确 toSchedule，避免连续修改时失真。无法还原的历史不能推定完整覆盖。
- 未覆盖日期以斜纹和文字说明，失败日期另有描边；title/aria-label 同时说明记录口径，不只依赖颜色。邻月单元格未加载时明确提示，点选切换目标月份后读取其详情。
- 来源/标题/结果按现有 escapeHtml 渲染；日期细节只打开本地记录或显式邮件/面试入口，没有自动网络读取或 AI 调用。
- 已完成行动保留原始 ISO 时间与选定时区；月历按照用户当前选定时区归日。邮件同步覆盖只提供检查记录，无法证明用户在应用之外未做其他行动。

## 边界

本轮为服务行为测试与 UI 静态复核，不代替真实窗口的热力样式、键盘选择或多次改期浏览操作。真实邮箱连接/系统通知另按对应子功能验收。没有可核验全天覆盖证据时持续显示未知/部分是正确行为；不应为了让日历更“完整”自动填成已知零。
