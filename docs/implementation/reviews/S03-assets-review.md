## 需要修复

1. **P1：损坏原件无法按提示重新导入修复。** `assets.cjs:39` 命中已有 hash 后直接调用 `file(old.id)`，存储副本缺失或损坏会再次抛错。用户持有正确原件仍无法恢复这份被历史申请引用的资产。实测：导入一个带 PDF 头的失败解析文件，修改资产目录副本，然后重新导入未修改的原始文件，仍得到“文件已变化或损坏，请重新导入原件”。建议验证导入缓冲区的 hash 后，以原 ID 原路径安全恢复副本，再重试解析；保留旧申请版本绑定和审计。补充损坏、缺失副本恢复用例。

2. **P1：混合 PDF 的扫描页被整体成功掩盖。** `assets.cjs:29` 只判断全文是否非空；`workbench.js:114` 仅在 `needs_ocr` 时显示 OCR 按钮。一页可提取文字、另一页为扫描图的简历会标记 ready，扫描页没有补识别入口。建议记录逐页状态、提示缺文字页，并允许对选定页或整个 PDF 主动 OCR；合并时保留已有页的来源与文本。待 OCR 接入时必须验收混合 PDF。

3. **P2：DOCX 全文被伪装为单一页/段。** `document-worker.cjs:10` 将整份 DOCX 放入 `{page:1,text:全文}`，UI 显示“第 1 页 / 段”。DOCX 没有这里可验证的分页，且全文通常包含多段；后续 AI 来源不能据此宣称第 1 页。应使用明确的来源类型和段落编号，或标记“DOCX 全文（无页码）”，并让结构化草稿保留该限制。

4. **P2：OCR 光栅化没有像素/原生内存预算。** `document-worker.cjs:22–26` 按 PDF 自带页面尺寸创建 Canvas，并把每页图像同时保存在数组。Worker 的 `maxOldGenerationSizeMb` 只约束 JS 堆，不能视作 Canvas、Buffer 的进程级内存隔离。页数上限仍不能限制单页超大尺寸。OCR 上线前应限制宽高、总像素和返回字节量，必要时缩放或逐页处理；加入超大页面拒绝测试。此项为代码检查，未运行会耗尽内存的攻击样例。
