## 初审问题（复审已修复）

1. **P2：用户无法取消正在进行的单个任务。** `src/services/resume-ai.cjs:69` 只暴露关闭服务时批量 abort，workbench 无取消命令；`src/ui/workbench.js:116–124` 提交后只有等待。关闭面板不会取消请求，仍可能产生供应商费用，成功后还会重新弹出草稿面板。建议提供可见任务状态与取消入口，任务 ID 在开始时可取得；取消标记保存在作业中，提交结果前复核 abort 状态。界面关闭需明确表示后台继续或实施取消，避免把关闭误解为撤回外发。
2. **P2：退出草稿后，已付费生成的结果无法重新进入。** `src/services/workbench.cjs:9–19` snapshot 不返回 aiJobs，也没有历史结果命令 / UI。任务持久化为 ready，但用户关闭草稿或重启后只能再次调用模型。failed 作业也没有恢复入口。应按附件提供任务历史、状态与“继续核对已有草稿”，失败可显式重试；资料已变化时保留旧结果供查看并说明为何不可采用。

## 已验证

- UI 明示正文加已确认资料 / PDF 页面图像的外发范围，显示供应商地址、模型和 BYOK 费用说明；需主动勾选，服务也验证 `confirmed === true`。不会把 BYOK 写成平台托管收费。
- 整理结果限制已知 group / key、整数索引、数量与值长度，quote 必须是对应页正文子串，value 必须可在 quote 中找到；重复字段与错误页号拒绝。此校验是原文证据约束，不是对 OCR 识别事实正确性的保证，人工核对仍必要。
- `sourceLabel` 保留 DOCX 段落“非页码”语义。UI 对原值、建议值、引文、来源均转义，并默认不勾选。
- 选择后续新增记录时重新压紧索引，同一记录选中的多个字段共享新索引，未选记录和已有记录不被覆盖。
- 资料 hash 变更拒绝整批采用；profile merge 在副本上处理全部字段，save 原子写并保留历史。
- 未确认任务不会调用供应商；模型失败保留原资料并记录 failed；OCR 页号不完整或重复时不记录结果。
- 模型请求禁重定向，超时 90 秒，响应体有大小限制，错误输出不会被直接采纳。

## 补充边界

- profile 文件保存和 aiJobs 的 adopted 状态为两个写入，不是跨存储事务。如果资料已保存后 job 状态写入失败，UI 将显示失败但资料已经改变。建议后续加恢复状态 / 提交凭据，避免对用户谎报“未修改”；当前不会因重试静默重复追加，因为 profile hash 已改变。
- 当前取消只会发生在 workbench close，异步 catch 可能随后访问已关闭 store；新取消机制应同时处理退出生命周期。
