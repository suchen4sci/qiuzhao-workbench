# 工作台使用与运维

本版本把个人事实、机会、投递计划、申请和事件分别保存。主实施状态见[实施台账](implementation/实施与审查台账.md)；它是本地可用功能与真实服务验收的边界记录。

## 第一次使用

1. 在设置 → 工作区管理新建空白目录；切换会重启。不要用虚构演示资料投递。
2. 在设置 → 个人资料与简历中维护事实。唯一事实源仍是 `知识库/profile.json`，界面保存会保留修订。求职偏好独立保存，不改变个人事实。
3. 导入 PDF/DOCX 原件，核对解析内容，再保存事实。扫描图片没有文字时需要配置 OCR；解析失败仍保留原件。AI 草稿需要你显式选择和确认，不能凭空补经历。
4. 在机会中手工建岗位，或读取一个公开岗位链接。读取只支持部分结构化公开页面；动态列表、需登录页面与尚未覆盖的公司须手工核验。当前没有全网自动发现承诺。
5. 加入计划、打开申请后，才产生本次资料与附件版本。规则快速填写免费可用；可随时滚动检查、手工修改、停止。验证码、声明和最终提交由本人完成。
6. 提交后用“确认已提交”登记实际时间和依据。打开页面、填写完成或上传成功均不会自动视为投递成功。

## 智能服务

- 自带 Key：设置服务地址、模型与密钥，费用由该服务商收取；平台不会同时扣托管额度。
- 托管：在设置 → 托管账号与额度配置已部署的服务，邀请码注册/登录。仓库没有默认生产地址。运营方部署参阅[托管服务文档](../hosted-service/README.md)。
- 字段识别：选定字段后，可选择 BYOK 或托管。只发送所示字段文字、栏目、标题和控件类型；文字本身可能含个人信息。托管先报价，再确认额度。返回建议仍须逐项勾选保存，之后主动点击快速填写。
- 托管任务断网：在 AI 设置 → 托管字段任务刷新、取消或沿用同一任务重试。不要为同一不明结果反复新建报价。关闭界面不取消服务器任务；返回原申请表单才能采用对应建议。
- 面试简报：为特定面试提供 1–5 个公开来源链接；个人经历默认不发送。事实引用逐字来源，推断和准备建议单独标注。可选连接 Brave Search 搜索公开线索，结果和真实内容仍需核实。已有手写笔记与生成结果分开保存。

## 邮件与提醒

邮箱使用只读 IMAP 授权码，凭据存入系统加密存储。可先导入 `.eml` 原文验证人工核对流程；自动规则默认不开启。只有窄规则能够明确识别的安排才可按配置自动处理，其他内容进入待确认箱。改期与取消保留原文依据，不以邮件已读替代任务完成。

本地提醒要求应用正在运行，系统通知还取决于 OS 授权。时区、每日摘要、提前量在设置 → 提醒与数据中配置；恢复运行后会补记错过的本地提醒并标注。没有部署云端常驻服务时，关机或退出期间不会持续监控。

## 旧版迁移

设置 → 提醒与数据 → 迁移旧版投递记录，选择旧版 `投递记录.json`，核对并勾选条目。原文件不修改。原记录完整保存为证据和机会笔记，同时建立待确认项；旧状态、模糊日期、轮次与附件路径不被当成已核验事实，因此不会自动创建已提交申请、面试或提醒。

已迁入的相同 ID/内容会跳过；同 ID 内容变化会提示人工核对，不覆盖新系统中的内容。没有记录 ID 的条目按完整内容去重，修改后的无 ID 条目可能形成新记录，需要在选择时检查。旧附件只保留路径文字，不自动读取、复制或上传。原文在机会详情继续可读；核对后再根据实际情况建计划、登记申请与事件。

## 备份与恢复

导出 `.qzb` 完整备份包含事实、历史、原件和本地业务数据，**文件未加密**，应保存到可信位置。系统密钥与网页登录态不导出。恢复时校验内容，在选定位置建立新的独立工作区；不会覆盖当前正在使用的目录。恢复后在工作区管理中导入新目录并重启，邮箱、托管账号和模型密钥可能需要重新连接。

## 发布与故障处理

源码开发使用 Node.js 24 或更新版本。桌面安装包内置 Electron；用户不需要另装 Node。数据位于所选工作区或应用用户目录，不写入安装目录。卸载应用前自行备份资料。当前没有自动更新、正式签名/公证，Windows 真机与生产服务验收见[发布验证](发布验证.md)。

发生错误时先保留原工作区和备份，再查看设置中的来源/邮箱/任务错误状态。来源读取失败不代表岗位关闭；支付跳转返回不代表入账；断网不代表托管任务失败。不要直接编辑 SQLite 来绕过确认或计费状态。运营方必须按托管账本、渠道回调与审计记录处理支付争议。

## 云端公开页监控

在「设置 → 云端公开页监控」连接运营方已部署的托管账号。服务端须启用云端监控；没有默认生产服务。逐项填写公开页面名称与链接并确认发送后，每页最多每日读取一次，最多 20 页。首次读取建立基线，后续结构化岗位内容变化进入通知箱，需你打开官网确认。没有岗位数据或读取失败不表示停止招聘。

关闭桌面应用后，仅已部署且持续运行的服务会继续检查；退出账号不会停用，请使用暂停或删除。服务全局停用时仍能删除已有配置。当前仅提供云端通知箱，刷新页面读取；不包含外部消息推送、邮箱同步或截止提醒。不要提交包含私人登录令牌的链接。

## 本机每日来源检查

先从「机会」或「邮箱与来源」读取公开岗位链接，再点「每日读取设置」，选择关联单位、开启每日检查并确认读取范围。最多启用 20 页；每页每 24 小时自动检查一次，依赖应用运行。恢复运行会补查到期页面，但无法重建停机期间已消失的内容。手动「重新读取」可额外即时核验。

新岗位或字段变化进入待确认箱，不自动导入或覆盖手改岗位。页面其他 HTML 变化不会重复生成相同岗位草稿。关注单位显示关联的已选页面是否成功、失败、陈旧或需人工核验，未关联页面的单位明确显示未接入。单页读取不代表公司全部岗位、分页完成或所有路线已覆盖。自动发现的 100 岗位 / 7 天独立来源基准仍未完成。

百度官网 `talent.baidu.com/jobs/list` 以及 `jobs/detail/GRADUATE|INTERN/<岗位编号>` 增加公开页面适配，可从 HTML 中的初始数据读取本页岗位，不执行脚本。列表显示实际读取页码、每页数量及网站报告总量，不自动遍历下一页。岗位草稿单独展示来源发布日期、更新时间、项目和方向；这些信息及页面有效标记均不代替开放状态、开放日期或资格核验。仍须人工核对单位、批次与原文后导入。结构变化或身份不一致会显示失败；本机网络的实际读取链路仍待验收。

## 可选公开线索搜索

在「设置 → 搜索连接」配置自己的 Brave Search API Key。密钥由系统钥匙串加密保存在当前工作区对应的连接存储，不包含在导出备份。保存连接不执行搜索；每次在「机会 → 搜索公开线索」或面试详情「搜索公司 / 产品线索」确认可编辑关键词和供应商费用后才发起一次请求。仅发送关键词及固定查询参数，不自动读取或发送个人资料、简历、邮件、浏览器内容。

每次只取第一页最多 10 条，当前工作区滑动 24 小时最多 20 次（失败尝试也计数），这是本地使用限制，不是账户全局或供应商额度。搜索摘要只是线索；选定 1–5 个原始链接后，仍需再次确认简报生成范围与模型/托管费用。机会页的线索先预填链接读取表单，仍需主动读取、核对公司和批次。

关闭或切换搜索面板会请求取消，供应商可能仍计费。已返回结果仅缓存在本次运行内，可从再次打开的搜索面板恢复查看；不会因恢复查看再次请求。重启后无缓存的已执行请求不会静默重发；重新搜索需新确认且可能再次计费。没有默认生产 Key，真实套餐价格与服务可用性需自行确认。

接口依据：[Brave Web Search](https://api-dashboard.search.brave.com/api-reference/web/search/get)、[认证说明](https://api-dashboard.search.brave.com/documentation/guides/authentication)。本轮完成模拟提供方测试与 Electron UI 测试，未调用真实付费搜索供应商。

## 按单位浏览与批量计划

机会列表按单位聚合，可展开比较不同岗位与批次。顶部路线、方向、城市、单位性质、搜索方案支持多选：同一维度任一满足，不同维度同时满足；单位数和岗位数按当前结果分别统计，不代表全网数量。已选项在切换筛选后保留，计数明确包含筛选隐藏项，可清空后重新选择。

「为勾选项安排计划」允许统一选择日期、优先级和计划提醒。最多 200 项；已有计划保留原安排，修改需打开该计划。单位和该单位岗位同时被勾选时，仅创建所选岗位计划；只有单位则创建待选岗位项。加入计划会同时关注所属单位，不计为投递或申请成功。计划提醒开关仍受全局本地提醒设置约束，关闭某计划提醒不会删除计划或改变每日摘要设置。

「导入单位清单」接受每行一个单位，或从表格粘贴名称、公开 HTTPS 链接、类型三列（制表符分列）。默认类型可选企业、招录机关、事业单位、院校；最多 200 行。先预览再勾选确认，同名同类型复用并保留原资料；不同类型不会误合并。导入只添加关注，不创建岗位或申请。清单重复项保留首次出现；别名或同名不同实体仍需人工核验，系统不会自动猜测合并。

### 机会反馈和每日摘要

机会卡上的「反馈」可保存不感兴趣、条件不符、已看过及原因；不感兴趣和条件不符可隐藏 7 天、30 天或直到关键条件变化。可在「查看已过滤」恢复，恢复仍按当前真实条件匹配。已有计划与投递记录保留。

本地提醒默认每天聚合一份机会与行动摘要，可改为每 7 天或关闭，可选择应用内记录和系统通知。应用未运行时无法准时提醒，恢复运行只生成当前期摘要；独立面试和截止提醒沿用各自安排。

机会摘要区分新开放、新发现在招、存量补充、开放待核实和关注变化，分别统计岗位及单位。采集日期不会替代开放日期；已见单位有新岗位按熟悉单位统计。无新增时如实显示零，可继续查看全部相关存量。从通知记录「查看全部机会」进入完整集合，逐条反馈或安排计划。

已实际进入视口的机会与已送达摘要分别留痕，后台加载不计作看过。关注变化依据工作台记录的关键字段变化；需要人工对照官方来源核验，不会自动覆盖人工记录。来源页面读取、待确认草稿和自动覆盖率仍须分别核验，不能把这些摘要当作全网发现保证。

偏好可按路线、性质、方向、城市、行业、工作方式、单位/院校和关键词编辑必须条件、优先条件与全局限制。一个维度多值任一满足，不同维度同时满足，多张方案卡之间任一满足；优先条件不会直接排除。含逗号的单位名或标签请用双引号包裹，已保存值会自动按此格式显示。模板只添加可编辑卡片，保存前会展示全部已加载样本的命中和不命中原因，确认后才生效。

来源内容有更新时，先核对单位和批次，再预览与已有岗位的差异。只有勾选字段会更新；不勾选可明确保留原值，人工资格、计划和申请不会随来源内容被覆盖。无稳定岗位编号或同页多个相似岗位时，需选择是新岗位还是某个已有岗位。旧草稿遇到来源新版本后不可继续采用；来源恢复为曾出现过的内容也会形成新一轮待确认。每次更新保留旧记录快照和读取证据，岗位详情可查看本次更新原文。

从投递计划中「添加后续事件」会带入对应申请或计划。独立添加面试也可选择同单位记录；切换单位会清空旧关联。未开始网申的计划可以直接关联面试，不会因此生成申请记录。简报会读取关联岗位说明；计划岗位更换或清空后，先修改面试并重新核对关联再生成。会议链接按用户点击在外部浏览器打开，查询参数和片段保留。

岗位详情的「按公告核验资格」支持多条可选资格路径；每条路径的条件同时满足。请粘贴公告原文，并仅在实际核对后勾选已核验。专业和证书名称是否必须严格一致应按公告明确选择，系统不自行推断等价。修改后会重新匹配；被过滤岗位仍可从「查看已过滤」修正规则。清空全部路径只会恢复为资格待核实，不会把它判定为已符合。

面试准备卡显示生成中、可阅读、需核对、生成未完成或尚无简报。下一场会优先展示，开始前 30 分钟至结束前提示临近或进行中；已完成、取消或已结束的场次不作为下一场。刷新生成失败时仍可阅读旧材料，修改面试安排、岗位或个人资料后会提示核对。

简报分段显示来源事实、待核实推断、个人经历依据和体验/交流问题，并保留来源读取时间。点击「打开来源」才会在外部浏览器打开。详情中的「导出简报与笔记」将当前安排、已有简报、来源和自己的笔记保存为 Markdown；无需 AI 配置或付费额度，也可仅导出手工笔记。

日历选定日期后，分别查看当日计划、实际完成、改期与状态变化。改期保留原日期和每次去向，同日修改开始、结束或截止时间也可追溯；从历史面试记录可直接进入简报和复盘，邮件核对产生的改期可查看对应邮件原文。完成热力仍按实际完成时间和所选时区归日，取消或撤销不计完成。

斜纹日期表示未覆盖；同步未完成显示边框和文字提示。有记录只说明部分行动已保存，邮箱某次检查成功也不代表全天完整覆盖。空白日期不再宣称零行动。顶部待办摘要始终显示今天，历史页标题和内容明确标注所选日期。

手工保存的单位和岗位链接会保留查询参数与页面片段（例如岗位编号或单页应用路由），支持 HTTP/HTTPS。来自公开页面的岗位链接也保留明确提供的参数和片段；若来源未提供有效的文本链接，则回到实际读取的来源页。公开页面抓取仍只接受公开 HTTPS，旧版看板导入继续按原规则去除敏感查询参数。

填表工作区的「核对已填字段」可选择自带 Key 或已登录的托管服务。先勾选疑似错误字段，确认本次发送范围与计费方式后，模型只接收字段名称、栏目与类型；网页现值和个人资料值在本机比较。核对页列出现值、资料原文、建议值与来源条目。多条经历须选择对应记录，再勾选确认替换；没有已确认事实时不生成答案。

采用前会重新核对页面、申请、资料版本和字段现值；发生变化需重新扫描。执行期间检测到输入会暂停后续项，已完成、需核对和未修改分别报告。纠错不改个人资料、永久字段规则、附件或网站提交状态。普通填写仍保留原有内容；复杂复合字段和自定义控件若无法安全核对会保留人工路径。托管纠错单独报价和结算：额外发送可用资料字段标识，具体资料值不外发。确认报价后预留额度，至少交付一项对应可用资料字段的建议才结算；无可用建议、失败或取消且未交付不扣除。未启动报价可直接取消。任务可从 AI 设置或纠错范围页的「托管纠错任务」刷新、取消、同任务重试或查看结果，重启后仍保留。采用前须返回原申请、原表单和相同资料范围，已有手改不会被旧结果覆盖。

### 邮件与 Offer 日期

邮件原文分别显示发件时间（邮件 Date 头）、服务器收件时间和本地导入时间。导入 EML 没有可靠收件时间时留空；旧记录的时间标识为来源未核验。

Offer 编辑页单独保存发出、收到、回复截止、入职 / 报到四个时间。回复提醒和日历排期以回复截止为准；不会用发出、收到或入职时间代替回复截止。历史通用操作截止会在编辑时带入回复字段供核对，未知日期请留空。

处理后续改期邮件时，先选择要更新的事件。表单保留已有信息，只合并同机构、同类型邮件中明确识别的日期；跟进邮件收到时间不会覆盖原 Offer 收到时间。保存前仍应核对原文。规则目前只提取明确的带时区 ISO 时间；复杂正文和附件继续进入待确认。

### 邮件自动改期与取消

邮箱设置有独立的“自动处理同一邮件线程中明确的改期、取消通知”开关，默认关闭。开启后，仅更新此邮箱规则创建、尚未人工修正、仍待办的唯一事件；要求同发件地址、明确线程引用、机构类型及轮次一致，发件与服务器收件时间均晚于已处理通知。邮箱发件地址匹配不证明发件身份。

改期会调整对应任务并撤销旧提醒；取消只取消事件与任务，不产生完成记录。人工修改或恢复事件后，后续邮件留在待确认箱。未知线程、多个事件、日期未完整解析、已知结束时间需同步修改、轮次冲突、撤回/作废/恢复通知、附件等都需核对。待确认页面会在有唯一线程依据时预选已有事件并回填保存内容，最终仍由用户确认。

此规则不根据单纯公司名称猜测更新对象。复杂正文可使用下述自带 Key 解析草稿，也可使用托管额度解析。


### 申请编号与邮件岗位关联

登记实际提交时可填写官网申请编号；计划详情的“核对 / 修改申请编号”支持补录、修正或清空，需填写核对依据。同一机构的不同申请不能使用相同编号。编号只接受官网原文中的字母、数字及 `. _ / -`；修改编号不改变提交状态，也不改写提交快照里的原始编号。

本地邮件规则识别独立行的 `申请编号：...`、`申请号：...`、`申请岗位：...`、`应聘岗位：...`、`岗位名称：...` 及相应英文标签。机构和明确编号 / 岗位必须唯一匹配已登记提交的申请，才会自动关联申请与计划；不会把草稿当作已投递。相同岗位跨批次、多编号、编号与岗位冲突、未知机构等留待核对。

待确认邮件中可查看关联依据、选择同机构申请；更新已有事件会保留其原关联供核对。没有明确标签时不猜单个申请；同机构存在多个已提交申请而邮件未说明岗位时，也不会自动新建或更新事件。


### 复杂邮件 AI 草稿

在待确认邮件中选择“AI 解析所选片段”，保留要发送的连续原文（最多 20000 字），核对模型供应商和费用说明后生成。附件、邮箱凭据、个人资料和其他邮件不会随该请求发送。若模型配置在确认后改变，会要求重新确认。正文中的敏感信息由你通过选择片段控制；自带 Key 的失败、取消也可能产生供应商费用。

结果展示字段原文、直接引用及可采用值，逐项勾选后只放入待确认草稿；不会自动创建、更新或取消事件。随后需在原邮件事件表单核对公司、岗位、申请关联和日期再确认。事件类型和取消/改期语义仍需人工判断，引用存在并不保证模型理解正确。

仅完整且可校验的日期能转换。原文没有时区时，可明确选择固定 UTC 偏移；没有足够年份、时间或时区依据的结果只展示原文，不允许直接采用。返回结果可从该邮件 AI 入口查看；支持停止，重启中断任务不会自动重试，已修改或已处理的草稿拒绝过期结果。采用记录和原草稿历史保存在本机。

解析入口可选择自带 Key 或托管额度。托管模式先展示报价与交付条件，再单独确认预留额度；只有交付可核对、可逐项采用的结果才结算，空结果、失败或未交付取消不结算。可从任务历史刷新、取消或核对结果。实际可用性取决于运营方是否配置 `mail-parse` 定价、模型与托管服务。

邮件处理后，原文页仍有 AI 历史入口。旧结果可只读查看，已采用、已处理或版本过期时不能覆盖当前记录；未采用托管副本仅在原服务账号登录状态下可访问。


### 普通填写的暂停与人工接管

点击“快速填写”后，网页上方显示接管提示。点击网页、按键或点击“暂停并接管”会停止本轮任务；界面显示“正在停止”时等待在途操作结束，之后才能直接编辑。首次接管点击/按键只用于暂停，不重放到网页，请再次点击字段或重新输入。这样避免自动填写与人工修改同时进行。

“继续填写 · 重新扫描”使用网页当前内容重新检查，只补充仍可填写的字段，保留已有值与人工修改。页面/框架导航也会暂停；退出网页时停止当前填写。暂停结果展示停止后重新检查的当前页面，不把中断的写入计为已验证完成。填入、网站保存和最终提交仍是独立状态。


## 每日偏好搜索

在「发现机会 → 每日偏好搜索」查看已保存偏好生成的查询，再选择每轮 1–10 次的预算并确认持续搜索费用。默认关闭；保存搜索连接本身不授权每日搜索。各方案和路线轮流检索，企业等路线展开方向别名；考研保留原研究方向，不套用企业招聘别名。不限制发布日期，以包含仍开放的存量线索；搜索命中不代表同时满足卡片全部条件，仍须核对原文、资格及开放状态。

应用运行时每分钟检查是否到期，每 24 小时最多一轮，与单次搜索共享滚动 24 小时 20 次的本机上限。查询较多时跨轮次继续，不在一轮用完全部；失败、中断、重新配置和重启均不会重放已预留的当轮请求。关闭面板不关闭已授权的每日搜索；可取消当前轮次，或取消「允许每日自动搜索」并保存以停用。偏好变化后停止继续搜索，需重新核对授权。

「查看已保存线索」在重启后仍可查看全部收到的结果，按 URL 去重、分页，保留每条查询依据、首次发现和最近发现时间。发现时间不是开放时间，搜索结果也不是申请资格依据。读取原文仍需主动核对并导入；未核验的搜索线索不会自动写入岗位、收藏、计划或投递。真实供应商 Key、网络、套餐额度和代表性来源召回测试仍是外部验证依赖。


## 首次使用与中途继续

空白个人工作区首次打开会显示六步引导：导入简历 → 核对我的条件 → 选择默认 PDF → 设置路线、偏好与每日摘要 → 关注单位 → 可选邮箱。各步复用原有文件、资料和偏好编辑器；导入只保留原件和解析结果，AI 整理及邮箱读取仍需各自明确授权。

“已核对，继续”检查已保存数据；未保存的资料须先保存或放弃，离开偏好编辑页的草稿会回到预览确认，不能被旧版本替代。未知事实可保留为空，解析失败可继续手工录入。每步可明确跳过，跳过状态与已核对分开记录；默认 PDF 和邮箱未设置时不会冒充成功。

“稍后继续”将当前步骤保存到工作区，重启后从今日横幅或「设置 → 首次设置进度」恢复。编辑器尚未保存的草稿不属于持久进度，关闭应用前请保存所需内容。完成后可从设置重新补充跳过项；损坏资料优先显示原有恢复入口，不当作空白资料重新开始。引导完成不代表招聘资格、邮箱认证或外部服务已通过验收。
