# AI 增强的配置与边界

## 普通用户：软件内 AI 字段识别

普通“快速填写”使用本地规则，不需要 API Key 或订阅。AI 增强默认关闭。

1. 点击“AI 设置”，填写兼容 Chat Completions 的服务地址和模型名称。
2. 服务地址填写前缀，例如 `https://你的服务地址/v1`；程序在后面追加 `/chat/completions`。云端需 HTTPS；本机模型可用 `http://localhost:端口/v1`。
3. 填写服务商 API Key；本机免密服务可留空。勾选启用后保存。服务费用由你配置的提供方收取。
4. 打开当前表单，点击“AI 识别字段”。程序只发送未知字段的名称、栏目、控件类型和通用字段目录，不发送简历事实值、整页 HTML、Cookie 或源码。标签文字本身可能含个人信息。
5. 核对建议并逐项勾选，保存对应关系。此时不会自动填写。
6. 点击“快速填写”，规则引擎读取本地资料并回读。已确认的字段关系保存到私人工作区，可在关闭 AI 后复用。

程序拒绝无效字段、跨栏目、人工字段及过期页面建议。低置信度结果不展示。验证码、附件、声明、缺少事实、已有值冲突与控件不支持仍可能需要人工处理。专用站点流程后会补填用户确认的映射；复杂页面以实际回读结果为准。

API Key 使用 Electron 系统密钥存储加密后保存在应用配置目录；UI 不回传已保存密钥。系统加密不可用时拒绝保存密钥。请求 45 秒超时，可点击停止；停止客户端请求不保证服务商已经取消计费。关闭 AI 不影响规则版。当前另有托管账号、报价与额度账本的工程实现，但没有默认生产服务，真实支付和生产定价仍待验收。字段纠错、简历/邮件草稿与面试简报的数据范围分别说明，不能把字段元数据范围套用于所有 AI 功能。

当前配置与范围见[使用指南](工作台使用与运维.md)和[实施台账](implementation/实施与审查台账.md)。历史方案见[项目实现与产品化方案](archive/planning-2026-10-02/项目实现与产品化梳理.md)，其“尚未实现”按历史版本理解。真实供应商质量与成本仍需独立验证。

## 开发者：Codex 自动修复

历史 Codex 修复能力保留给 Windows 源码开发，安装包不包含修复脚本，默认不启动。它不同于普通用户的 AI 字段识别：Codex 可以读取完整页面、资料和源码，以当前用户权限访问网络、修改代码与资料。

请确认 `codex --version`、`codex login status` 正常，CLI 支持原有 runner 所需参数；设置：

```powershell
$env:QIUZHAO_WORKSPACE = 'D:\我的求职资料'
$env:QIUZHAO_ENABLE_AI = '1'
$env:QIUZHAO_ENABLE_CODEX_REPAIR = '1'
npm start
```

此模式启动后会用旧的“AI读取”控制替换字段识别按钮，执行读取页面 → 修正规则 → 测试 → 热更新 → 快速填写 → 独立回读，最多 3 轮。宽权限操作只应在信任的开发环境中使用，不自动最终投递或代签声明。Windows 路径和热引擎的遗留限制仍需整理，不属于当前跨平台用户服务。

私有日志在 `desktop/artifacts/ai-reader/`，可能含个人信息。不要上传日志、浏览器配置目录、Cookies 或 app-connection.json。远程调试只绑定本机，不转发给其他机器。
