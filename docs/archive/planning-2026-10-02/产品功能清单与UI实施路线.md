# 秋招工作台：产品功能清单、UI 与五阶段实施路线

更新：2026-10-02。承接《秋招全流程功能与 API 规划》，补充简历自动导入、AI 资料整理、个人资料/PDF 管理与网申附件自动上传。

本文是下一轮开发的范围与验收依据。现状来自当前工作区代码检查，不代表已完成真实网站、模型或邮箱联调；本文新增能力均尚待开发。

本日设计修订：根据用户对实际界面的反馈，取消此前“八个一级页面”和“个人资料一级导航”方案，改为四个主入口加底部设置，网申以真实浏览器任务打开，增加自动面试准备。详细交互与当前截图见[界面重设计与智能工作流](界面重设计与智能工作流.md)。

## 1. 产品目标与已明确的需求

最终软件应让用户在一个工作台内完成：上传简历 → 自动整理个人资料 → 管理不同 PDF 简历版本 → 发现并关注招聘机会 → 自动填写与上传附件 → 同步招聘邮件 → 管理测评/面试/材料任务 → 看板与提醒。

已经确定的产品要求：

- 简历导入是主入口，不能要求普通用户先手工编辑 `profile.json`。
- 文件导入后自动保存到内部文件库，并启动解析；支持 AI 整理结构化资料。
- 个人资料和 PDF 在“设置 → 个人资料与简历”完整页面管理；首次使用引导进入，日常不占据常驻侧栏。
- 用户选定本次投递文件后，系统自动执行上传，不把每次手动选择系统文件作为正常流程。
- 保留五个建设方向：①待办与事件管理；②邮箱同步；③今日看板与提醒；④公司关注与招聘监控；⑤资料可视化与托管 AI。
- 第⑤项中的资料中心是填表和自动上传的前置依赖，安排在首批实施；托管 AI 可后置。五个方向是工作包，不应机械理解为全部依次完成。

## 3. 最终 UI 信息架构

保留桌面应用，只保留一条全局侧栏，包含四个主入口与底部设置。首次使用进入简历导入/资料引导，此后默认“今日”。业务模块数量不等于侧栏入口数量。

| 一级页面 | 主要区域 | 用户能做什么 | 核心状态 |
|---|---|---|---|
| 今日 | 行动清单、日历页签、最近变化、待确认 | 查看今天要做什么、处理任务、进入面试准备 | 无任务、临期、逾期、待确认、同步异常 |
| 机会 | 发现岗位、关注公司、岗位/公司详情 | 查看自动整理的岗位档案，关注开放与截止，开始申请 | 未开放、开放中、滚动、关闭、核验未知 |
| 投递 | 列表/阶段视图、投递详情、事件时间线 | 查看自动同步的进度，继续真实网申，追溯资料与附件 | 草稿、已投递、测评、面试、Offer、结束 |
| 面试准备 | 按面试组织的公司、业务、产品、岗位简报 | 了解产品，关联自身经历，准备问题，记录面后复盘 | 待准备、生成中、可阅读、部分缺失、待刷新 |
| 设置（底部） | 个人资料与简历、邮箱连接、AI、提醒、数据/账号 | 维护资料和 PDF，配置连接与偏好 | 资料不完整、连接正常/过期、服务不可用 |

全局顶栏提供统一搜索与通知入口。网申从“机会/投递 → 开始申请/继续填写”进入浏览器任务页；待办和日历放“今日”页签；邮箱原文从事件证据打开，连接配置归设置。通知和待确认不再各开一个常驻侧栏。正式首页不默认进入练习页。

### 关键页面布局

**设置内的个人资料页**：仍为完整可编辑页面，不塞进小弹窗；采用“资料 / 简历与附件 / 导入记录”页签，分类使用页内锚点或标签。平时隐藏细节，缺资料时从具体任务直达缺失项并返回。必填与完整度由目标用途决定。

**简历与附件页签**：左侧文件列表，右侧 PDF 预览和文件详情。展示语言、用途、版本时间、大小、有效/归档状态、关联岗位、默认版本。支持“设为默认”“绑定岗位”“重新解析”“查看历史使用”“导出”“归档”。

**网申浏览器**：真实招聘网站占据主体，显示域名、导航和当前岗位；执行期间全局导航可收窄。一条紧凑任务工具栏显示本次简历、开始/暂停/继续/接管及进度。仅在缺资料、冲突或检查结果时打开可关闭的详情抽屉，不常驻个人资料全文。结果区分字段回读、附件接收、网站保存、申请提交。

**今日总览**：顶部给出今日任务、今日面试、逾期任务、待确认数量；主区域按时间和紧急程度列出具体行动。侧区显示未来七天、关注公司的新变化、同步异常。统计与日历复用同一任务查询口径，不在各页面重复写不同算法。

**面试准备**：确认面试事件后按公司、业务与该岗位自动生成有来源的准备简报，包含产品入口/体验任务、岗位相关性、个人经历证据、待补知识与可提问题；与投递详情复用同一份内容。

## 4. 简历导入 → AI 整理 → 更新个人资料

### 4.1 用户路径

1. 新用户点击/拖入简历，第一版支持 PDF 与 DOCX；扫描 PDF 走 OCR 分支，无法读取、损坏、加密文件给出明确处理方式。
2. 系统将原件复制到用户工作区内部文件库，生成文件 ID 与内容哈希；不能只记一个会随用户移动而失效的下载目录路径。
3. 自动识别文本层；有可靠文本则直接解析，扫描页才调用 OCR/视觉能力。不同模型对文件和图片支持不同，不能把原始 PDF 直接塞进当前文本字段映射接口。
4. 按用户配置自动启动 AI 整理；未配置或服务不可用时保留原件，允许手工维护资料或稍后重试。
5. 提取姓名、联系方式、教育、实习、项目、校园经历、荣誉、语言、技能等，保留原文、文件版本、页码/片段定位和缺失项。
6. 自动保存整理草稿。首次导入直接呈现预填完整表单，一次“采用并保存”即可生效；无需逐字段重新输入。
7. 已有资料时展示“新增 / 修改冲突 / 重复 / 未提及”，支持批量采用新增、按项处理冲突、保留原值和撤销本次合并。
8. 保存后更新运行时资料源，填表助手与资料页立即使用同一已保存版本；运行中的一次填表固定其起始快照，避免执行一半突然换资料。

“自动导入”覆盖保存文件、提取、整理和生成更新方案；有冲突时集中核对。可以后续增加用户选定的“仅自动补充空字段”策略，自动变更仍需留记录且可撤销。AI 不得以“整理”为由补造日期、数字或经历。

### 4.2 合并与更新原则

- 简历没有出现的已有字段不自动删除；新上传的岗位定制简历通常并不包含用户所有经历。
- 同一次实习、项目、教育记录通过稳定 ID 与身份线索合并，不按数组位置覆盖，不因中英文名称不同直接重复新增。
- “至今”和日期精度保留原样；只有年份时不能生成任意月份，只有月份时不能生成具体日。
- AI 改写的简介与个人事实分开，原始描述可以查看并恢复；首次目标是准确提取，不默认压缩正文。
- 删除经历或文件时显示实际依赖；已投递快照不随个人资料编辑而被改写。
- 演示资料与真实工作区明确隔离，导入真人简历不能和虚构示例混合。

### 4.3 三种对象必须分开

| 对象 | 作用 | 更新关系 |
|---|---|---|
| 结构化个人资料 | 供表单编辑、搜索与填写取值 | 采用导入结果或手工编辑后更新 |
| PDF/DOCX 原文件及版本 | 供预览、下载和实际投递 | 保存不可变版本；不能因资料改动而假装原 PDF 已同步 |
| 单次投递快照 | 记录当时的资料版本、所选经历与实际上传文件 | 后续资料更新不覆盖历史 |

第一版“修改个人资料”不等于“重新排版生成 PDF”。界面应提示关联文件可能需要更新，并允许导入新版。简历排版生成器属于后续独立增强，不是本轮完成文件管理的前提。

## 5. PDF 文件管理与网申自动上传

### 5.1 文件中心的最小能力

- 导入 PDF/DOCX，保存原文件、MIME/格式、大小、哈希、导入时间、版本、来源和解析状态。
- PDF 内嵌预览、缩放和翻页；DOCX 首版可显示文件信息并用系统打开，不以尚未建设的转换能力冒充预览。
- 分类：简历、作品集、成绩单、证书、其他；支持中英文、岗位方向与默认版本标签。
- 同内容文件识别重复；同文件名不同内容视为不同版本，不能覆盖后丢失历史。
- 投递显式绑定文件 ID/版本；更新默认 PDF 不自动改掉已投递历史或执行中的上传任务。
- 归档文件不再自动候选；清理前显示引用，支持备份恢复。若用户要求彻底删除则执行明确的数据删除流程，并保留不含原文的“文件已删除”历史占位。

### 5.2 自动上传完整链路

```mermaid
flowchart LR
  A[岗位绑定 PDF / 用户默认 PDF] --> B[识别当前网站附件要求]
  B --> C[校验类型、大小、用途和版本]
  C --> D[执行文件选择与必要的上传动作]
  D --> E[等待网站接收及校验结果]
  E --> F[核对附件记录与可用的保存后回读]
  F --> G[记录本次上传版本与证据]
```

正常情况：用户首次选好默认版本，或对特定岗位选好版本；点击“填写并上传”后自动完成，不再弹系统文件选择框让用户每次找文件。

文件选择优先级：本次投递明确绑定版本 → 用户对该用途配置的默认版本。多个候选、类型不匹配、页面已有不同附件或网站要求不明时，才请求选择/处理；AI 不凭文件名猜哪份应该发给招聘方。

技术上可复用现有 Playwright：标准 file input 用 `setInputFiles()`，动态选择器用 `filechooser` 事件；复杂上传器需要站点适配。官方能力见 [Playwright 文件上传](https://playwright.dev/docs/input#upload-files)。文件选中后仍须检查网站响应，不能把该调用成功等同于服务器已保存。

上传状态细分为“准备中、文件已选择、上传中、网站已接收、持久化已核验、失败、无法核验”。只有文件名可见时显示证据有限，无法核验时不报告完整成功。网络超时重试前先检查是否已经上传，避免重复文件。

PDF 限制不满足时，说明具体大小/类型要求，支持选择其他已存文件。DOCX 改扩展名不能当作 PDF；转换/压缩要生成可预览的新版本并保留原件。文件选择及明确的附件上传按钮可以自动执行，最终网申提交仍按既有提交边界处理；上传完成不等于申请已投递。

招聘网站可能在上传简历后自动解析并覆盖表单。因此执行器需区分：要求先解析附件的站点先上传、等解析结束，再填表和核验；纯附件站点可填表后上传。不能统一写死“最后一步上传”并忽略网站对字段的修改。

## 6. 数据与模块需要怎样更新

### 数据新增

- `Asset`：文件身份、受管存储位置、哈希、类型、大小、状态。
- `ResumeVersion`：对应 Asset、语言、用途、默认关系、派生版本关系。
- `ImportJob`：文件 ID、提取方式、处理进度、错误、解析结果与重试记录。
- `ProfileRevision / FieldEvidence`：资料修订、字段来源、用户确认、差异和撤销所需信息。
- `ApplicationSnapshot`：当次投递锁定的资料修订、经历选择、文件 ID/哈希。
- `UploadAttempt`：目标页面/附件用途、选定文件版本、执行状态、核验依据、失败原因与幂等信息。
- 复用上一份规划中的 Company、Opportunity、Application、Event、Task、Reminder 和连接同步记录。

第一版继续以 `profile.json` 为已确认资料运行源；由统一资料服务校验并原子写入，写前检测版本冲突并保留备份。任务和文件元数据可进入本地数据库；不要同时让数据库和 JSON 各自成为可独立修改的事实主库。大文件保存在受管文件目录，数据库存身份与关系。

### 代码检查与更新范围

| 现有位置 | 需要改什么 | 回归关注 |
|---|---|---|
| `src/ui/index.html`、`app.js`、`style.css` | 全局导航、资料页、文件页、导入流程、统一状态反馈 | 现有浏览器、复制、选择经历、结果面板继续可用 |

| `src/dashboard-import.cjs`、`job-context.cjs` | 投递上下文关联资料/附件快照 | 已投递历史对应真实版本，不再只写“简历附件待核验” |
| 看板 `store.mjs`、`server.mjs`、`public/app.js` | 多事件、多任务、统一统计、文件/投递关联 | 数据迁移、日期/时区、完成后清理旧提醒 |
| 打包配置与数据目录 | 携带解析/预览必要资源，保存受管文件与备份 | macOS/Windows 安装后可用；升级不丢资料、文件和设置 |
| 文档、演示与旧 TODO | 用真实状态替换“附件一律手动”等旧描述 | 未接入能力不能宣传上线，数据上传说明覆盖简历/邮件 |

### AI / 普通功能与内部接口

普通模块负责文件存档、文本解析器/OCR 调度、哈希、预览、版本、合并校验、上传执行与核验。AI 负责理解文本/版面和提取候选事实，不能直接写任意资料或选择任意本地文件上传。

拟新增内部职责：`importAsset`、`startResumeExtraction`、`getImportResult`、`applyProfileChanges`、`listAssets`、`bindApplicationResume`、`uploadBoundAsset`。托管 HTTP 模式可对应 `/v1/assets`、`/v1/resume-extractions`、`/v1/profile-revisions`；这些是设计，不是当前已存在的 API。本地资产元数据与原文件默认留在本机，是否上传正文/图片由明确的解析模式决定；不能把内部接口名称误解成全部文件必须上云。

新增简历提取不能继续宣传为“只发字段标签、不发个人信息”：文本模型会收到简历正文，扫描件识别可能发送页面图片。用户在启用时应能理解处理范围，且可选择保留原件但不启用云端解析。

## 7. 按五个方向落地的开发顺序

### 工作包 ①：待办与事件管理

- 拆开岗位、投递、事件、任务，先支持手工新建、编辑、完成、取消与改期。
- 建立投递详情、事件时间线；测评截止、预约截止、正式面试分别记录。
- 验收：一岗位三个并行任务独立展示；完成一项不影响其余两项；改期保留来源。

### 工作包 ②：邮箱同步

- 单个邮箱服务商先形成完整链路：连接、增量收信、邮件提取、匹配投递、确认落库、错误恢复。
- 模板规则优先，AI 理解复杂邮件；重复/转发、第三方发件人和改期需要专门样本。
- 验收：重复同步不重复建任务；预约截止不当成面试时间；断连状态可见、重连可恢复。

### 工作包 ③：今日看板与提醒

- 统一今日、逾期、未来七日查询，支持日历与任务列表；再做系统通知和每日摘要。
- 持久化通知队列、完成取消、改期撤销、重启和休眠补偿。
- 验收：计数按任务不按岗位；通知不重复；停止/完成任务后不再提醒；明确本地运行条件。

### 工作包 ④：公司关注与招聘监控

- 先支持人工添加官网/岗位链接和一批核验过的官方来源，再扩展搜索发现。
- 公司、届别、岗位、开放/截止与证据关联；记录最近成功核验与异常。
- 验收：每个日期有来源；无日期不编造；网站失败不判成岗位关闭。

### 工作包 ⑤：个人资料、文件中心与托管 AI

- **⑤A 首批基础**：统一导航、资料可视化编辑、PDF/DOCX 导入、文件库、PDF 预览、默认版本、岗位绑定。
- **⑤B 导入智能化**：文本解析、AI 整理、扫描件路径、差异合并、来源和撤销；复用当前自带 Key 配置但使用新任务接口。
- **⑤C 网申闭环**：自动上传选定附件、结果核验、资料与文件投递快照；网站解析后重新核验字段。
- **⑤D 产品服务**：后置建设托管登录、模型代理、额度和用量；需要全天在线时再接常驻云端调度。
- 验收：用户上传简历后无需手改 JSON 就能建立资料、预览 PDF，并在支持的测试站点完成自动填写与上传；历史投递始终可追溯到当时版本。

### 依赖顺序与交付里程碑

| 里程碑 | 覆盖工作包 | 交付给用户的可用结果 |
|---|---|---|
| M1：资料与附件闭环 | ⑤A/B/C + 统一 UI 框架 | 上传简历 → 采用结构化资料 → 管理 PDF → 自动填写并上传 → 核验与保存投递快照 |
| M2：手工进度闭环 | ① + ③基础 | 手动录入多个事件与待办，在今日页/日历查看并接收本地提醒 |
| M3：邮件驱动闭环 | ② + ③完善 | 邮件变成待办，改期/取消自动形成更新建议，处理后同步看板和提醒 |
| M4：招聘机会闭环 | ④ | 关注公司，监控开放/截止，进入已有投递流程 |
| M5：普通用户服务化 | ⑤D；按需加入全天在线能力 | 无需自配 Key 的 AI 服务，用量透明，后台能力按实际部署提供 |

M1 与后续事件模型设计可以同步设计，但不是要求一次把所有界面和云端系统写完。先交付可独立使用的真实闭环，再启用下一个导航入口。
